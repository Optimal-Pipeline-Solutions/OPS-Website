OPS Website — Site Upgrade Concept

Decisions, rationale, and technical patterns for the site-upgraded.html design iteration

Author: Chris Babb  |  Date: 2026-06-22  |  Status: Concept / In Progress

Concept — Not Production Working File: F:\web site ideas\site-upgraded.html Preview: /index-update.html on GitHub Pages

1 Overview

site-upgraded.html is an iterative upgrade to the production index.html, developed in F:\web site ideas\ and pushed as index-update.html on the live GitHub Pages repo for preview. It shares the same section structure, content rules, and component system as production but introduces a semantic color palette, improved card treatment, and a SCADA fixed-parallax background spanning two dark sections.

Critical constraint: F:\OPS Website\index.html is the live production file and must never be edited directly. All design work happens in F:\web site ideas\site-upgraded.html. Changes are previewed at /index-update.html before any promotion decision.

3 SCADA Fixed-Parallax Background

The Control Room section and the Operations Expertise section (immediately below) share a fixed-parallax SCADA diagram background — the same technique used by the About page hero background.

The Pattern

<section id="control-room" class="ops-section" data-theme="dark"
         style="background:#050810; position:relative;">
  <div style="position:absolute;inset:0;
              background:url('scada-bg.svg') center/cover no-repeat;
              background-attachment:fixed;
              opacity:0.35;"></div>
  <div class="section-inner relative" style="z-index:5; ...">
    ...content...
  </div>
</section>

The same background div is repeated verbatim at the top of the Operations Expertise section, causing the SCADA image to visually continue across the section boundary as the user scrolls — reinforcing that both sections belong to the "control room" part of the narrative.

Why This Pattern

Three prior approaches failed before this solution. All attempts to use position:fixed on a DOM element caused the SCADA graphic to leak over unrelated sections regardless of parent overflow, z-index, or JS toggling.

ApproachWhy It Failed
GSAP ScrollTrigger with position:fixed Section height < viewport height caused onLeave to fire before onEnter — callbacks permanently misfired. SCADA showed on full page.
IntersectionObserver + visibility:hidden/visible threshold:0 fires when 1px of section enters viewport at bottom edge. With position:fixed, the SCADA then covers all sections still visible above. No CSS mechanism clips a position:fixed element to its parent's bounds.
position:fixed + inline opacity/visibility CSS Same root cause — position:fixed removes the element from normal flow; parent overflow:hidden has no effect on fixed children.
background-attachment:fixed on position:absolute div Works correctly. The div is positioned absolutely within the section (clipped to section bounds). The background image is fixed relative to the viewport within those clipped bounds. Matches the About page pattern exactly.

scada-bg.svg Requirements

When extracting an SVG for use as a CSS background image, the host page's <style> block does not apply. All CSS classes used by the SVG must be embedded inside a <defs><style></style></defs> block within the SVG file itself.

The SCADA background is static — no animated particle circles, no live-data element IDs. The original #cr-scada inline SVG (with live data IDs) is preserved in the DOM as display:none for reference.

5 Magazine-Style Services Layout

The Services / "What We Do" section uses a magazine two-column layout (mag-row, mag-visual, mag-content) with GSAP scroll-triggered entrance animations — content slides in from the left/right alternately on scroll.

Animation note: The scroll-triggered entrance animations require GSAP ScrollTrigger. If the page is visited with GSAP not yet initialized (e.g., very fast scroll before CDN loads), cards may appear in their initial off-screen position. This is a CDN load-order concern, not a bug in the implementation.

7 Promotion Path

When the upgrade concept is approved for promotion to production:

  1. Verify index-update.html on the live GitHub Pages URL renders correctly with no broken assets
  2. Confirm scada-bg.svg is present at repo root (already pushed)
  3. Copy site-upgraded.html content to index.html, adjusting any path references
  4. Push via GitHub Manager (or direct MCP push)
  5. Update Obsidian note status and this document's status badge

Never directly edit index.html. Always make changes in site-upgraded.html, test via index-update.html, then do a deliberate copy-over. This keeps a clean audit trail and prevents accidental pushes of broken states to production.
